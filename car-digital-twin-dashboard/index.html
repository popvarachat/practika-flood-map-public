C—

ปิดได้จริงหรือยัง

Action Completed ≠ Effective ต้องมี Verification Period, recurrence check และหลักฐานก่อน QMR Gate

—Avg Effectiveness /20
QMR Priority · สิ่งที่ต้องจัดการก่อนเรียงจาก Process Risk
Decision Rules · อนุมัติ / ส่งกลับ / Reopenใช้เป็น Gate ก่อนเซ็น
STOP

ส่งกลับ ถ้า Requirement ไม่ชัด, Root Cause เป็นอาการ, Action ไม่ตรง Cause หรือไม่มี Effectiveness

VERIFY

ตรวจเพิ่ม ถ้ามีหลักฐานแนบแต่ยังอ่านไม่ครบ หรือ Action ดูเป็นระบบแต่ยังไม่มี recurrence check

GO

อนุมัติปิด เมื่อ Cause → Action → Evidence → Effectiveness เชื่อมโยงและตรวจสอบย้อนหลังได้

QMR Closure GateSystemic closure principle
1 · Opening

Problem statement + evidence + requirement ต้องตั้งโจทย์ให้ถูกก่อนออก CAR

2 · Root Cause

ห้ามหยุดที่ “คนลืม / ไม่ระวัง / สื่อสารไม่ทั่วถึง” ถ้าระบบยังเปิดช่องให้เกิดซ้ำ

3 · Corrective Action

KYT / Morning Talk / กำชับ / อบรม ไม่ใช่ Systemic Closure เว้นแต่พิสูจน์ว่า competency gap คือ root cause จริง

4 · Effectiveness

ต้องมีหลักฐานทวนสอบหลังใช้มาตรการ และเช็ค recurrence ก่อน QMR อนุมัติปิด

DATA GOVERNANCE

Why this is a Digital Twin

Case + Document + Lineage + Quality
Case Twin

หนึ่ง CAR = หนึ่ง canonical entity มีวันที่ หน่วยงาน Category Severity Status และ Issue Detail

Document Twin

อ่าน PDF ทุก revision ลงฐานข้อมูล พร้อม Page Text, Form Widgets, Annotation และ File Attachment ไม่ได้หยุดแค่ชื่อไฟล์หรือ metadata

Source Lineage

Internal Twin เก็บ Drive lineage เต็มรูปแบบ ส่วน Public View ซ่อน URL / Drive ID และข้อมูลระบุตัวตน

Data Quality

ข้อมูลว่าง/ขัดแย้งถูก flag และภาพหรือ attachment ที่ text extraction อ่านไม่ครบถูกส่งเข้า Vision Review Queue แทนการเดา

Public-safe publication policy: ชื่อบุคคล อีเมล เบอร์โทร Drive URL/File ID, raw form fields และหลักฐานภายในไม่ถูกเผยแพร่ใน GitHub Pages
